# frontend/ — экспорт из Claude Design

## Файлы
- **mir-pod-solncem.dc.html** — ГЛАВНЫЙ файл, финальная версия дизайна после полного промпта доработки (форум «Страны» с Иришкой, онлайн-панель, видеообзоры, вход/профиль, уведомления, поиск, «О нас», куки, юр-футер, QR). Это источник правды по дизайну.
- support.js — рантайм Claude Design, нужен для работы dc.html.
- mir-pod-solncem-v1.dc.html — старая версия (референс, в прод не идёт).
- mir-pod-solncem-offline.html — офлайн-бандл для просмотра без сборки (открой в браузере, чтобы посмотреть дизайн).
- uploads/ — изображения, использованные в дизайне.
- design-sync-notes.md — заметки синхронизации Claude Design.

## Как это использует Codex (фича F09)
Экспорт — единый HTML-файл формата Claude Design, а НЕ готовый Vite-проект. Поэтому фича F09 выполняется в два шага:

**Шаг 1 (перенос).** Codex создаёт `frontend/app/` — стандартный Vite + React проект и переносит туда разметку, стили и логику из `mir-pod-solncem.dc.html`, разбивая на компоненты по разделам (Layout, Feed, Forum, Reviews, Subscribe, QA, Profile, Notifications, About). Дизайн переносится 1:1: цвета, типографика, анимации, обе темы, мобильная версия. Исходные dc.html-файлы не удаляются — остаются как эталон для сверки.

**Шаг 2 (API).** Локальные данные заменяются на REST API по docs/BACKEND_SPEC.md (client.ts + hooks), как описано в prompts/P09_frontend_wiring.md.

## Известные хвосты дизайна
- Реакции на комментарии (👍❤️🔥😂) в экспорт не попали или не находятся поиском — при переносе в F09 добавить по описанию prompts/P00_FULL_claude_design.md §6.

## Разработка и проверка frontend

Команды выполняются из `frontend/app/`:

```bash
npm ci
npm test
npm run build
```

`npm test` запускает Vitest в среде jsdom. Frontend-тесты проверяют React-компоненты и API-интеграции без обращения к реальным внешним сервисам; полный вход через Telegram дополнительно проверяется вручную после настройки домена бота в BotFather.
