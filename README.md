# МИР ПОД СОЛНЦЕМ — платформа-сайт турагентства «Под солнцем»

**Кодовое имя проекта:** `mps-platform` (МПС)
**Что это:** «сайт нового образца» — журнал-платформа в стиле Substack, адаптированный под турфирму. Лента фишек, отзывы, форум по странам, вопрос-ответ юристу/менеджеру, связка с Telegram-ботом подбора туров. Позже — премиум-подписка и Android-приложение.
**Методика:** Harness Engineering (обвязки) — walkinglabs/learn-harness-engineering.
**Исполнитель кода:** Codex (подписка до конца месяца). **Навигатор/архитектор:** Claude. **Дизайн фронтенда:** Claude Design.

## Порядок действий (пошагово, чтобы не запутаться)

### Шаг 1. Создай репозиторий и вложи обвязку
```bash
mkdir mps-platform && cd mps-platform
git init
```
Скопируй в корень репо 7 файлов обвязки из этой папки: `AGENTS.md`, `init.sh`, `feature_list.json`, `claude-progress.md`, `session-handoff.md`, `clean-state-checklist.md`, `evaluator-rubric.md`. Скопируй туда же папку `docs/` целиком (Codex будет читать ТЗ и спеку). Сделай `chmod +x init.sh`. Первый коммит: `git add -A && git commit -m "harness: обвязка проекта МПС"`.

### Шаг 2. Фронтенд — ГОТОВО ✓
Дизайн доработан по полному промпту и уже лежит в `frontend/` (главный файл `mir-pod-solncem.dc.html`). Открой `frontend/mir-pod-solncem-offline.html` в браузере, если хочешь посмотреть глазами. Дальнейшие правки дизайна — только через Claude Design, с заменой файла в репо.

### Шаг 3. Запускай Codex по сессиям
Одна сессия = один промпт = одна фича. Открываешь Codex в корне репо и вставляешь промпт по порядку: `P01` → `P02` → … → `P10`. Каждый промпт начинается с команды прочитать `AGENTS.md` — это включает обвязку. **Не давай два промпта в одну сессию.** После каждой сессии:
1. Проверь, что Codex обновил `feature_list.json` (статус фичи → `passing` + доказательство в `evidence`).
2. Проверь запись в `claude-progress.md`.
3. Прогони `clean-state-checklist.md` (сам или попроси Codex).
4. Коммит.

### Шаг 4. Оценка на майлстоунах
После P05 (конец M2) и после P08 (конец M3) прогони `evaluator-rubric.md`: попроси Codex (или меня, Claude) оценить работу по 6 измерениям. Если Revise/Block — чини до продолжения.

### Шаг 5. Деплой
P10 выкатывает всё на твой VPS (Нидерланды, nginx + systemd, как у остальных ботов). Домен со старого сайта «купить тур» перенаправляем на платформу — старый сайт не обновляем, он закрыт (решение Сергея на встрече).

## Главные правила (чтобы не сломать методику)

1. **Одна фича за раз.** В `feature_list.json` только одна фича может быть `in_progress`.
2. **Нет доказательства — нет done.** Статус `passing` ставится только после реально выполненной верификации из поля `verification`, с записью результата в `evidence`.
3. **Никакого placeholder-кода.** Заглушки «TODO потом» запрещены AGENTS.md.
4. **Фронтенд = Claude Design, бекенд = Codex.** Codex не переделывает дизайн, он подключает фронт к API (P09).
5. **Каждая сессия начинается с `./init.sh`** и чтения `claude-progress.md` + `feature_list.json`.

## Что осознанно отложено (не делаем сейчас)
Премиум-подписка и оплата (YooKassa), Android-приложение (TWA/WebView), рекламные места, аватар-блогерша для Instagram, автоворонки — всё это M5, после того как платформа «раскачается» (прямое решение Сергея: «платную подписку — это всё потом, вначале надо раскачать»).
